# 2026-09-16 ADR

## ADR-20260916-004：配图高级操作进入独立大弹窗，Drawer 仅保留预览入口

- 日期：2026-09-16；状态：Accepted；确认人：`arden`。
- 关联需求：用户明确指出缩放、裁剪、旋转、翻转等图片高级功能直接铺在文章详情 Drawer 内不合理，要求点击图片后进入单独弹窗操作。`change_id = BUGFIX-IMAGE-EDITOR-SEPARATE-MODAL`；版本门禁返回 `required_version = 0.2.10`。
- 背景：原实现把大图查看、裁剪参数、历史操作和保存动作纵向堆在可调宽 Drawer 内，挤压文章详情信息，并把“查看配图”和“进入编辑会话”混为一个界面。图片编辑还拥有脏草稿、不可取消的原生保存、全屏查看与放弃确认，多层关闭若共用 Drawer 容易让一次 Escape 或遮罩点击同时关闭多个界面。
- 信息架构决定：配图页签在 Drawer 内只保留当前已保存配图预览、明确的“高级编辑配图”入口、生成血缘与当前阶段生成动作；点击预览或入口后才加载并打开独立高级编辑 Modal。缩放、平移、全屏、裁剪比例与边界、旋转、翻转、撤销、重做、恢复原图和保存全部只在该 Modal 内出现。Modal 最大宽度为 `1240 CSS px`，保留 `16–32 CSS px` viewport gutter，最大高度服从 viewport 且 body 独立滚动；窄窗沿现有响应式规则回流。
- 会话与关闭决定：Drawer、编辑 Modal、全屏查看和放弃确认分别拥有关闭路径。任一图片编辑层打开时，底层 Drawer 禁止 Escape 与遮罩关闭；全屏 Escape 只关闭全屏。干净会话直接关闭，脏草稿的关闭按钮、Escape 与遮罩统一进入确认；继续编辑保留草稿，明确放弃才卸载会话。原生保存 Promise 未完成时所有关闭入口保持锁定，完成后才恢复；最终关闭把焦点还给本次实际点击的图片或按钮。
- 读取与错误决定：Drawer 预览只调用既有只读图片命令，不加载高级编辑锁；高级编辑只在显式打开后读取。后台预览刷新失败时保留旧图，同时显示错误与零 AI 重试，不能静默吞掉失败。保存继续携带完整乐观锁并保留既有人工编辑血缘、冲突草稿和新文章包语义。
- 理由与影响：详情抽屉恢复为浏览和阶段操作界面，高级图片工具获得稳定的大画布与明确会话边界；打开已生成图片仍是只读瞬时查看，不会误触 AI，也不会把 Drawer 关闭误认为放弃图片草稿。该变化不新增 AI 请求、数据库字段、文件格式或产品阶段。
- 风险：多层 Modal 的 Escape、遮罩与焦点恢复存在竞态；保存 IPC 不能取消，因此保存中只能锁定关闭而不能假装中止。预览和编辑器分别读取同一受管图片，刷新失败时可能短暂显示旧图，但界面会明确标识该状态并允许重试。
- 验证：定向 React 回归 `4` 个文件、`38` 项测试通过，覆盖高级控件只在独立弹窗出现、干净/脏草稿关闭、遮罩与 Escape、继续/放弃、保存未决锁定、全屏分层、焦点返回、Drawer 不被误关以及重新生成后的预览和编辑源刷新；TypeScript 类型检查与 CLI 版本回归 `9/9` 通过，Cargo 锁定元数据解析成功。本次未执行完整前端测试、真实窗口 E2E、打包、签名、推送或发布候选验收。
- 恢复或调整标准：若真实窗口证明 `1240 CSS px` 上限、viewport gutter 或窄窗回流不适用，可在保持独立编辑会话和关闭层级的前提下调整尺寸；若未来加入涂抹、滤镜、多图或不可取消之外的长任务，必须另行定义工具状态、资源上限和取消语义，不得重新把高级工具塞回 Drawer。

## ADR-20260916-003：Grid 固定六列且无横向滚动，云文档连接器以显式版本文件上传起步

- 日期：2026-09-16；状态：Accepted；确认人：`arden`。
- 关联需求：用户明确要求优化表格显示且不出现横向滚动条，并增加可连接飞书等在线云文档、把最终 Markdown 或 HTML 上传同步过去的连接器模块。`FEATURE-CLOUD-DOCUMENT-CONNECTORS` 的版本门禁返回 `required_version = 0.2.8`，同一未发布功能周期不重复提升 Minor；独立可感知布局优化 `BUGFIX-GRID-NO-HORIZONTAL-SCROLL` 返回 `required_version = 0.2.9`。
- 范围决定：连接器是四阶段内容 SOP 之外的显式交付动作，不增加自动执行的第五阶段。首版实现通用非秘密连接器配置边界和一个飞书云空间 transport；用户在格式页选择连接器与 Markdown/HTML，并再次确认后，把带当前配图 Data URL 的自包含 `.md`/`.html` 文件上传到指定文件夹。首版不把文件静默转换为原生飞书文档，也不做批量、覆盖、增量或双向同步。
- 飞书协议决定：固定调用官方 `https://open.feishu.cn/open-apis`，使用企业自建应用 App ID/App Secret 获取 tenant token；测试连接只列取目标文件夹，真实同步使用 Drive 文件上传接口。客户端禁止重定向、限制超时与响应体、限制文件为 20 MB，任何失败都不自动重试。用户不能配置任意连接器 API 根地址。
- 安全与持久化决定：App Secret 使用独立于 AI Provider 的系统凭据服务，WebView、SQLite、日志、错误和历史只知道秘密是否存在。schema v10 新增非秘密连接器配置、独立凭据引用/待清理集合和同步记录。同步记录绑定任务、文章包、连接器修订与格式；相同键成功后直接复用，防止双击或重复确认制造重复远端文件。删除配置保留非秘密历史并安全清理未使用秘密。
- Grid 决定：原十列改为“选择、文章信息、正文、简介、配图、格式”六列；文章信息格聚合总体状态、版本、创建/更新时间、错误与详情动作。表格使用 `table-layout: fixed`，阶段单元格、动作、文本预览和图片预览均可收缩；移除 `1840px` 最小宽与 Grid 横向滚动容器。960px 最小窗口下所有字段和动作仍在当前行可见。
- 理由与影响：用户继续保留类似飞书多维表格的一行一文章操作密度，同时不再需要左右拖动才能看到后续阶段。连接器先解决“生成完还要手工复制”的核心交付成本，又把真实外部写入与 AI 生成、保存配置、只读测试明确分离，为后续增加其它云文档 transport 留出稳定 core 边界。
- 风险：部分消费端不会渲染 Markdown/HTML 内的 data URI；首版优先保证单文件自包含和不泄露本机路径。飞书 App 权限与文件夹授权由租户配置决定，真实环境仍需用户提供隔离文件夹执行手动验证。上传 POST 在网络结果不确定时不会自动补发，用户需先到飞书检查再决定是否重试。
- 验证门禁：core 覆盖配置修订、默认位、启停删除和同步资格；SQLite 覆盖 v9→v10 与二次迁移；本地 HTTP 夹具逐字段核对 token、只读列文件夹和 multipart 上传且证明无自动重试；命令覆盖陈旧版本/缺秘密零出站和幂等复用；React 覆盖秘密不回填、连接测试、删除确认、当前格式确认同步，以及 Grid 六列、字段保留和无滚动容器。真实飞书联网、打包、签名、推送与发布候选不由本次日常实现冒充。
- 恢复或调整标准：若真实租户要求原生 Docx 块、HTML 导入、附件资源拆分、覆盖同一远端文件、OAuth 或批量交付，必须先定义格式兼容、远端身份、重试/结果未知、冲突与权限生命周期，不能在当前单文件上传上隐式增加副作用。若最小窗口下六列无法保持可用，应优先改进单元格层级与响应式信息密度，不恢复页面级横向滚动。

## ADR-20260916-002：格式使用并列页签与安全渲染，并在复制边界动态嵌入受管配图

- 日期：2026-09-16；状态：Accepted；确认人：`arden`。
- 关联需求：用户明确否定 Markdown/HTML 上下堆叠，要求改为并列选项卡，补齐两种格式的配图和解释后显示模式，并要求升级版本。`change_id = BUGFIX-FORMAT-TABS-RENDERED-PREVIEW`；版本门禁返回 `required_version = 0.2.8`。
- 背景：既有格式页同时纵向展示两个源码块，抽屉内浏览路径长，也没有解释后预览。规范 Markdown 与确定性 HTML 只保存正文，配图作为独立受管文件存在；直接把绝对路径、远端临时 URL 或重复 Base64 写入规范产物会泄露宿主路径、膨胀 SQLite 和全部包历史，并使图片编辑后的格式血缘难以保持一致。AI Markdown 还允许原始 HTML，不能直接注入 WebView DOM。
- 信息架构决定：格式页改为等宽并列的 Markdown/HTML 选项卡；每个格式内共享“源码/渲染效果”模式，默认 Markdown 与渲染效果。两项选择由应用根 Jotai store 在本进程跨路由保留，新进程恢复默认。这是用户本次明确批准的产品信息架构差异，并同步记录于 `docs/GUI_APP_PROFILE.md`。
- 图片与复制决定：规范 Markdown、HTML 和数据库 schema 不变。格式页活动且当前文章有图时，只按文章 ID 调用既有 `load_article_image` 安全命令；前端在内存中分别组装 Markdown 图片语法与 HTML `figure/img`，复制完整 Data URL。源码界面用明确省略号折叠图片负载但不改变复制内容；有图而读取失败时禁用复制并允许零 AI 的重新读取，绝不静默导出缺图版本。任何投影均不得包含绝对路径、`file://` 或方舟临时 URL。
- 渲染安全决定：Markdown 的解释结果复用 Rust 已确定性生成的 HTML；HTML 预览使用同一规范产物。预览先递归复制标题、段落、列表、引用、代码和表格等固定白名单结构，丢弃全部原始属性、图片、脚本、样式、表单、嵌入对象、SVG/MathML 和未知主动子树，再放入空权限 sandbox iframe；文档 CSP 只允许内联样式和受管 `data:` 图片，明确禁止脚本、连接、对象、子框架、表单与 base URI。
- 理由与影响：用户可在一个固定高度区域快速切换两种格式，并直接比较源码与最终视觉效果；复制内容真正包含当前配图，同时不改变 core 的规范产物、持久模型、审批历史或生成阶段。图片读取和模式切换都是只读行为，不调用 AI、不产生 token 或费用。
- 风险：Data URL 会增大剪贴板内容，部分外部编辑器可能不接受 Markdown data URI；当前选择优先提供无需额外文件即可复制的自包含结果。若未来需要通用文件发布，应单独定义带相对资源路径的导出包，不能回退为泄露本机路径。固定高度预览内部滚动属于当前 Drawer 的有界布局，不改变窗口或 Drawer 尺寸契约。
- 验证：前端完整 `23` 个测试文件、`166` 项测试通过，覆盖并列页签、根状态默认与保留、源码/渲染切换、两种含图复制、Base64 折叠、无图零 IPC、读取失败阻断与重读、沙箱/CSP、主动内容剥离及既有详情/Drawer/工作台回归；CLI 版本回归 `9/9` 通过，`cargo check --workspace`、TypeScript 类型检查、本次变更文件 ESLint/中文注释与格式检查通过。全量前端 lint 仍被本次变更前已有的 `PageSessionState.test.ts` 缺少中文声明注释阻断。本次未执行真实窗口 E2E、打包、签名、推送或发布候选验收。
- 恢复或调整标准：若目标平台明确拒绝 data URI、文章需要多图排版、必须保留可信链接属性，或真实内容证明固定高度/默认渲染模式不适用，应以新的稳定需求定义资源包、白名单或模式默认值；不得直接放宽 WebView CSP、允许原始 HTML 注入或持久化宿主绝对路径。

## ADR-20260916-001：生成指标只保存 Provider 原值，创建时间不可变并作为默认排序键

- 日期：2026-09-16；状态：Accepted；确认人：`arden`。
- 关联需求：用户要求四个生成阶段显示真实运行耗时和 token 用量，并让文章默认按不可变创建时间倒序排列。`change_id = FEATURE-GENERATION-METRICS-CREATED-SORT`；版本门禁返回 `required_version = 0.2.7`，同一未发布功能周期不重复提升 Minor。
- 背景：既有阶段尝试已经持久化开始和结束时间，但 Grid 只显示状态；文本适配器只读取总 token 且没有写入尝试，图片适配器不读取 usage。文章只有会被编辑、生成、保存图片和审核持续更新的 `updated_at_ms`，因此“最近更新”不能回答文章最初创建顺序。缩略图读取和后台刷新使用转圈，也容易与真实生成混淆。
- Provider 用量决定：core 使用逐字段可空的 `TokenUsage { input_tokens, output_tokens, total_tokens }`，并随真实 `StageAttempt` 原子保存。Chat Completions 只把响应中的 `prompt_tokens`、`completion_tokens`、`total_tokens` 映射为输入、输出、总量；OpenAI-compatible 图片只读取 `input_tokens`、`output_tokens`、`total_tokens`；火山方舟图片只记录其实际返回的 `output_tokens`、`total_tokens`。字段或整个 usage 缺失时保持缺失，不按 Prompt、字符、图片像素、模型上限或其它字段补算。Provider 已返回 usage 后，即使产物校验、本地保存或方舟临时图片下载失败，原值仍随对应失败尝试保存。官方契约依据为 [OpenAI Chat usage](https://help.openai.com/en/articles/10478918)、[OpenAI Images SDK schema](https://github.com/openai/openai-node/blob/main/src/resources/images.ts) 与 [Volcengine Ark Runtime 图片 schema](https://github.com/volcengine/ark-runtime-go/blob/main/arkruntime/model/images/oas_schemas_gen.go)。
- 本地阶段决定：Markdown 到 HTML 的格式转换不调用 Provider，成功尝试固定保存输入、输出、总量均为 0，并在界面标记“本地处理”；调试 Fixture 不是 AI Provider，不伪造 token 用量。
- 时间与动效决定：`queued` 与 `running` 是唯一显示生成转圈的阶段状态；只有 `running` 使用尝试开始时间建立秒级时钟。成功、失败、中断、取消和过期等终态只显示最后一次真实尝试的持久开始/结束耗时。缩略图读取、打开详情、首次或后台查询不得启动生成动效或计时；详情历史逐字段显示 token 与实际耗时。
- 创建时间决定：`ArticleTask.created_at_ms` 在新文章构造时与初始时间一次写入，此后所有 `touch`、编辑、重新生成、人工图片保存、审核、恢复和查询都不得改写。工作区 schema 升至 v9；旧文章优先从阶段尝试开始、包历史捕获、批准历史和已有人工配图编辑时间中选择最早正数证据，完全没有其它证据时才回退 `updated_at_ms`。已存在的正数创建时间永远保留。
- 排序决定：Grid 增加创建时间列与“创建时间”排序项。新进程默认按 `created_at_ms` 倒序，相同时间按稳定文章 ID 倒序；更新时间、标题和状态仍可由用户选择。排序只保留在根级进程内状态，不写 SQLite、URL 或设备存储，真正退出后恢复默认。
- 理由与影响：用户可以区分“任务正在生成”与“界面正在读取”，并看到供应商真实报告的费用相关遥测，而不会被估算值误导。不可变创建时间恢复稳定的录入顺序语义，同时保留更新时间用于观察最近变化。新增字段向后兼容，旧 usage 明确显示“Token 未提供”。
- 风险：OpenAI-compatible 服务可能使用不同或部分 usage 字段，严格只读已知真实字段会显示缺失，这是预期的失败开放兼容；旧数据只有更新时间时无法证明更早创建时刻，只能透明回退。秒级显示来自本地当前时间，但终态一律回到持久开始/结束时间，避免把渲染时钟当审计值。
- 验证：以 core 的旧/新数据、创建时间不变与 usage 原样持久化测试，Provider 的文本/图片/Ark 字段与缺失 usage 测试，worker 尝试持久化测试，以及 React 的 queued/running/终态转圈、实时秒数、Token、详情明细、默认排序和稳定平局测试为门禁。本次不执行构建、真实 AI、真实窗口 E2E、打包、签名、推送或发布候选验收。
- 恢复或调整标准：若未来需要价格估算、模型计费换算、Responses API 专用字段、跨设备排序偏好或服务端创建时间，必须另行定义数据来源、精度、货币/模型版本与迁移；不得把当前缺失字段静默补算或让可变更新时间重新承担创建语义。
