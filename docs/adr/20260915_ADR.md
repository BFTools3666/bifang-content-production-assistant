# 2026-09-15 ADR

## ADR-20260915-008：详情阶段动作与 Grid 统一为精确单步生成

- 日期：2026-09-15；状态：Accepted；确认人：`arden`。
- 关联需求：用户要求详情 Drawer 的阶段按钮只能操作当前阶段，不能以“从当前阶段继续”暗中带跑后续步骤；缺少前置阶段时必须在按钮附近明确说明。`change_id = FEATURE-DETAIL-STAGE-GENERATION`；版本门禁返回 `required_version = 0.2.7`，同一未发布功能周期不重复提升 Minor。
- 背景：Grid 已有带乐观锁、目标阶段 worker、单步运行记录和配图付费确认的 `generate_article_stage`，但详情仍调用独立的 `regenerate_article_stage`，后者启动完整 worker 并可能自动排队后续阶段。相同业务动作因此在两个入口呈现不同执行范围、Provider 要求和计费交互。
- 取代关系：本决定取代 `ADR-20260915-003` 中“详情的既有继续运行语义保持独立”以及只允许 Grid 提供真正单步入口的范围；该 ADR 的单步状态机、版本、运行记录、依赖、Provider 和计费边界继续有效，并扩展到详情入口。
- 决定：详情正文、简介、配图和格式按钮直接复用 Grid 的单步请求与后端命令，不新增并行执行路径。未开始显示“生成当前阶段”，其它终态显示“重新生成当前阶段”；成功只保存目标产物与尝试，不自动继续。保留“重新生成整篇”和“仅重试失败阶段”作为范围不同的显式动作。
- 依赖与提示：Grid 与详情共用同一最早缺失判断。正文要求非空标题；简介要求成功正文及其产物版本；配图要求成功正文、简介及各自产物版本；格式要求正文、简介、配图全部成功并存在当前受管产物。旧的过期产物可查看但不能满足依赖。按钮下方持续说明单步边界，禁用时按最早依赖、目标 AI 配置和运行锁顺序给出可处理提示。
- 竞争、版本与计费：详情携带用户所见行版本和文章包版本，后端在冻结凭据前及持久写入时复核。首次单步复用当前包，已执行阶段按既有 core 规则创建受保护新包；目标 worker 只收口一个阶段。配图沿用当前 Provider ID/修订、模型、尺寸、水印、结果不确定警告和逐次付费确认，取消零出站且一次确认最多一个请求。
- 接口收敛：删除已无调用的前端 wrapper、Tauri 注册和 `regenerate_article_stage` 外层命令，避免 WebView 仍可触发隐式续跑；core `regenerate_stage` 继续保留，供完整重新生成和 `queue_single_stage` 的安全版本化使用。单步确认弹窗使用高于 Drawer 的 Portal 层，确保详情入口可见且可操作。
- 风险与验证：主要风险为 UI 复制依赖矩阵、陈旧详情点击、图片确认被 Drawer 遮挡以及 loading/错误落错阶段。共享纯依赖函数、React 详情回归、命令边界回归和 Rust 单步预检覆盖这些边界；本次不执行真实 AI、完整 E2E、打包或发布候选验证。
- 恢复或调整标准：若未来需要“从当前阶段继续后续 SOP”，必须作为名称、范围和计费影响都独立的显式动作重新批准；不得复用当前阶段按钮或恢复已删除的隐藏 IPC。

## ADR-20260915-007：配图人工编辑保留 AI 原图并以新文件、新文章包提交

- 日期：2026-09-15；状态：Accepted；确认人：`arden`。
- 关联需求：在文章详情 Drawer 的配图页签提供安全、可保存、可恢复的基础编辑器，且不能覆盖
  AI 原图、AI 血缘或批准历史。`change_id = FEATURE-ARTICLE-IMAGE-EDITOR`；版本门禁返回
  `required_version = 0.2.7`，同一未发布功能周期不重复提升 Minor。
- 背景：既有配图只保存单个 `image_ref` 和 AI `image_lineage`，WebView 通过只读 data URL 查看；
  若直接覆盖该文件或把人工编辑伪装成图片生成尝试，将失去原图恢复能力、污染真实尝试账本，并
  让重复 JPEG 编辑产生级联损失。旧工作区的当前、包历史和批准历史也都只有各自图片引用。
- 领域决定：`ArticleArtifacts` 增加向后兼容的 `original_image_ref`、独立
  `image_edit_lineage` 与递增 `image_edit_revision`。人工血缘只记录来源 AI attempt、编辑 UUID、
  Unix 毫秒时间和规范化编辑参数；既有 `image_lineage` 与 `StageAttempt` 原样保留。每次保存先
  快照当前包，再创建派生文章包；批准历史不可变。新 AI 图片成功时以新图片重置原图引用、人工
  血缘与编辑修订。
- 参数决定：裁剪坐标统一使用 `0..1_000_000` 的整数相对坐标，宽高必须非零且不越界；旋转只
  接受顺时针四分之一圈 `0..3`，翻转为两个布尔值。Rust 固定按“裁剪→旋转→水平翻转→垂直
  翻转”执行，所有人工版本都从 AI 原图重新解码，不从上次派生图继续压缩。
- 存储与安全决定：WebView 只取得原图 data URL、像素尺寸、当前规范、编辑修订、可编辑性和
  禁用原因；聚合文章视图中的当前、包历史和批准历史必须同时清空 `image_ref` 与
  `original_image_ref`。Rust 只读取规范化后仍位于受管根目录的文件，限制为 `25 MiB`，以魔数
  接受 PNG/JPEG/WebP，并在 `4096×4096` 与 `128 MiB` 分配预算内完整解码。输出统一从内存编码
  为 PNG，以 `create_new` 独占创建新 UUID 文件并完整写入、同步；不得覆盖或删除原图和旧派生图。
- 一致性决定：只读接口返回行版本、包版本、AI 图片 attempt 和人工编辑修订；保存必须全部原样
  带回并在写文件前与仓储提交时各校验一次。目标文章过期、排队或运行时允许查看但禁止保存。
  提交或持久化失败只删除本次新文件并保留前端草稿；并发变化返回稳定冲突，用户重新载入后决定。
- 迁移与恢复：工作区 schema 升至 v8。所有旧 schema 的当前产物、每份包快照与每份批准快照都
  以自己的 `image_ref` 初始化原图引用，不能跨版本借用；迁移不读取、复制或删除图片文件。恢复
  AI 原图只是把编辑规范改回全图/零旋转/零翻转，仍需用户明确保存为新派生版本。
- GUI 决定：编辑器是独立高内聚组件；提供 `25%–400%` 缩放、适应窗口、`100%`、平移、全屏、
  重置查看，自由与 `1:1`/`4:3`/`16:9` 裁剪、左右旋转、双向翻转、撤销/重做、恢复原图和保存。
  查看操作零写 IPC；未保存关闭详情必须确认。Grid 缩略图缓存身份同时包含 AI attempt 与人工
  编辑修订，保存后不能继续显示旧图。
- 影响与理由：新增本地文件会增加受管目录占用，但换取可恢复原图、不可变历史、无 JPEG 级联
  和清晰审计。选择 PNG 派生格式避免重复有损编码；若输出超过 `25 MiB` 则失败关闭而不降质静默
  重编码。活动批次中的其它文章不构成全局禁用，目标文章状态和乐观锁才是保存权威门禁。
- 风险与验证：主要风险为裁剪整数映射、旋转/翻转次序、解压炸弹、路径逃逸、两阶段文件/数据库
  提交和前端重复点击。对应使用 core 状态测试、角点像素测试、伪造魔数/超维/逃逸测试、冲突后
  新文件清理测试、原图字节不变测试、schema 迁移测试、严格 IPC 与交互测试覆盖。此次不执行
  Tauri 打包、真实窗口 E2E、Windows 验证、真实 AI 请求、推送或发布，因此不形成候选验收结论。
- 恢复或调整标准：若后续增加滤镜、文字、画笔、任意上传、导出格式选择或跨平台色彩管理，需
  重新定义编辑规范、存储预算和预览一致性；若长期文件增长需要清理，只能在证明当前、包历史与
  批准历史均未引用后另行设计回收，不能把本决定解释为允许删除历史图片。

## ADR-20260915-006：文章详情 Drawer 支持有下限的宽度调整与设备记忆

- 日期：2026-09-15；状态：Accepted；确认人：`arden`。
- 关联需求：用户要求文章详情 Drawer 可以拉宽并记忆上次宽度，同时内部控件随宽度自适应，且拖动不能小于明确的最小宽度。`change_id = FEAT-RESIZABLE-DETAIL-DRAWER`；版本门禁返回 `required_version = 0.2.7`，同一未发布功能周期不重复提升 Minor。
- 背景：原 Drawer 固定使用 Mantine `lg` 的 `620 CSS px`，无法按长正文或格式内容扩宽；同时 `withinPortal = false` 让 fixed Drawer 嵌在带水平起点的 `AppShell.Main` 中，实际右边界超出 WebView，导致标题、按钮、页签和正文被裁切。通用会话状态规则又没有为用户明确要求的跨启动宽度偏好提供边界。
- 尺寸决定：保留 `620 CSS px` 默认宽度，左边缘手柄允许在 `480 CSS px` 到当前 WebView 宽度之间连续调整；窗口小于偏好值时只临时夹取可见宽度，窗口恢复后继续使用原偏好。拖拽只在结束或取消时落盘，键盘提供 `ArrowLeft`/`ArrowRight` 每次 `24 CSS px`、`Home` 最小、`End` 当前最大，并同步暴露 separator 的最小、最大和当前值。
- 持久化决定：宽度是用户明确批准的设备级布局偏好，使用独立 `localStorage` 键 `bifang-content-production-assistant:article-details-drawer-width`；缺失、非数值、低于最小值或存储不可用时回退默认宽度。该例外不扩展到文章内容、当前详情、页签、筛选、选择、Provider、Prompt、凭据或其它业务状态。
- 布局决定：恢复 Mantine 默认 body Portal，使 Drawer 相对完整 WebView 定位；手柄固定在 Drawer 左边缘且不随内容滚动。Drawer 内容根、页签和面板统一允许收缩，六个页签和动作组按可用宽度换行，长文本断行，图片和格式块保持在内容宽度内，不使用横向裁切掩盖不可达控件。
- 理由与影响：默认视觉尺寸保持不变，用户可为编辑长正文主动换取更大空间，并在下次启动继续使用；最小宽度保护表单、按钮和页签的基本可操作性。Portal 修正同时消除现有 AppShell 偏移造成的右侧控件缺失。
- 风险：Drawer 拉到接近 WebView 全宽时会暂时遮住 Grid，这是模态详情的预期行为；设备存储被清理后回到默认宽度。若浏览器存储拒绝访问，功能仍可在当前运行内调整，但不会跨启动记忆。
- 验证：GUI 专项回归 `6/6` 覆盖默认/最小/最大宽度、指针拖拽、结束时持久化、重挂载恢复、非法存储回退、视口缩放恢复、键盘操作、生产环境 Portal 归属与六个页签存在；与现有工作台回归合并为 `28/28` 通过，TypeScript、ESLint/中文注释和变更文件格式检查通过。真实窗口的手感与跨应用重启记忆仍交由用户人工复核。
- 恢复或调整标准：若未来需要每个文章、窗口或工作区独立宽度，必须重新定义偏好作用域、迁移与清理；不得把当前设备级单值静默扩展为业务数据或云同步配置。

## ADR-20260915-005：方舟 TOS 下载兼容受限透明代理 Fake-IP，并提供一次性真实链路探针

- 日期：2026-09-15；状态：Accepted；确认人：`arden`。
- 关联需求：用户要求真实 E2E 必须能够通过火山方舟生成并取得图片，允许先建立单独方舟程序定位反复失败；随后明确说明本机使用 Clash，并允许把本次方舟地址设为直连。`change_id = BUG-ARK-REAL-E2E-PROBE`；版本门禁返回 `required_version = 0.2.6`。
- 背景：真实工作区证据显示当前 Ark v3 POST 已成功并返回非空临时 URL，但下载尚未发出即失败。本机 Clash TUN 把官方 TOS 主机解析到 `198.18.0.0/15` 的 benchmark Fake-IP；原下载门禁把该网段与一般保留地址一起拒绝，因此在供应商已经生成、可能计费之后丢失产物。现有 loopback HTTP 契约测试无法覆盖这一宿主网络形态，统一下载错误又隐藏了具体失败阶段。
- 下载决定：继续只接受北京 TOS 官方 HTTPS 后缀、443、无 URL 凭据或片段的地址，保持 TLS 主机名校验、禁止重定向、Bearer 不转发、25 MiB 上限、MIME 与魔数校验。DNS 答案全为公网地址时沿用原路径；只有全部地址都属于 `198.18.0.0/15` 时才把它们分类为透明代理合成地址并允许固定连接。公网与 Fake-IP 混合、Fake-IP 与其它地址混合、其它私网/链路本地/保留地址及非官方主机继续失败关闭；`198.18.0.0/15` 不被提升为通用公网地址。
- 诊断决定：同一桌面二进制增加显式 `--ark-image-probe` 模式。`preflight` 只读当前 SQLite 快照，按默认位选择已启用方舟配置，通过版本化凭据引用检查系统钥匙串，验证模型、参数与端点，绝不发生成请求。`execute` 还必须携带付费确认和已存在的独立输出目录，复用正式 Ark transport、固定无文章数据 Prompt、一次最多一个 POST 且零自动重试；成功图片完成 Base64、魔数、完整像素解码后，以新建的私有文件保存。
- 秘密与证据：探针不得接收命令行 API Key，不输出凭据引用、密钥、Prompt、Authorization、响应正文、完整临时 URL 或签名查询；只输出阶段、稳定安全错误、非秘密 Provider 修订、请求次数、MIME、字节数、像素尺寸、本地输出路径和请求 ID 是否存在。工作区以只读 SQLite 连接加载，不执行建表、迁移、恢复或持久化。
- 计费与恢复：预检为零生成请求；真实执行必须在紧邻请求前取得用户对可能费用的明确确认。POST 结果未知或生成后下载失败仍不可自动重试，第二次尝试必须重新确认。外部 Clash 直连只是当前宿主辅助配置，不得成为产品正确性的唯一前提。
- 理由与影响：严格官方域名与 TLS 身份已经把请求目标绑定到火山 TOS；局部接受整组 Fake-IP 可以兼容透明代理，同时不放宽任意 URL 或一般内网访问。独立探针把配置、凭据、生成、下载、解码和保存结果变成可复核证据，避免继续依赖无法定位阶段的 Grid 失败状态。
- 验证：Rust 工作台回归 `134/134` 通过，覆盖纯 Fake-IP、全公网、混合答案、其它私网、非官方主机、URL 凭据、脱敏下载原因、现有方舟请求体、无秘密下载和探针参数/图片解码。零计费预检证明当前配置与钥匙串就绪、生成请求数为 `0`，并复核 SQLite 写入数为 `0`。用户已在本次热重载后的 macOS 应用中手动确认“生成测试图片”成功显示真实方舟生成图片；为避免重复计费未再发第二次请求。该结论属于开发级人工 E2E，不替代正式发布候选验收。
- 恢复或调整标准：若 Clash/Mihomo 改用其它合成网段、方舟迁移对象存储域名或需要跟随重定向，必须重新评估域名、TLS、DNS 分类与签名 URL 泄露面，不得把新网段或主机静默加入通用允许列表。

## ADR-20260915-001：删除当前 AI 连接时保留历史血缘并撤销凭据引用

- 日期：2026-09-15；状态：Accepted；确认人：`arden`。
- 关联需求：用户确认一个 AI 连接已经不用于正文、简介或图片步骤后，应能直接从连接列表删除，不应再被不可见的历史执行绑定阻止。`change_id = FEATURE-PROVIDER-DELETE-PRESERVE-HISTORY`；版本门禁返回 `required_version = 0.2.4`，同一未发布功能周期不重复提升 Minor。
- 背景：旧规则把当前步骤分配和历史文章包冻结绑定都视为删除门禁。界面只显示当前步骤用途，因此一个显示“尚未用于任何步骤”的连接仍可能因失败文章的冻结绑定返回 `PROVIDER_DELETE_REFERENCED`，用户无法从当前页面理解或完成删除。
- 取代关系：本决定明确取代 `ADR-20260913-001` 中“被任何执行绑定引用的 Provider 不能删除”及其严格删除风险说明；该 ADR 的启停、初始数据、Prompt 和真实 E2E 其它决定继续有效。
- 决定：删除只以当前正文、简介、图片步骤分配为业务门禁。历史执行绑定不再阻止删除当前连接；删除事务保留绑定中的 Provider 非秘密配置、Prompt 和文章血缘，但清空目标 Provider 在所有历史阶段绑定中的 `credential_ref`，不改动同一绑定里的其它 Provider。
- 凭据生命周期：删除事务收集当前映射和目标历史绑定中的全部凭据引用。只有不再被其它当前 Provider 或历史绑定引用的条目进入现有可重试凭据清理队列；系统凭据库失败不回滚已删除的非秘密配置，并以待清理状态继续重试。
- 重试语义：已删除连接不会被历史文章暗中继续调用。受影响旧阶段的普通重试返回现有 `PROVIDER_NOT_CONFIGURED`，用户需要选择当前 AI 后执行重新生成以建立新文章包绑定；已经启动并在内存中冻结的批次仍按原有取消和收口规则处理。
- 理由与影响：连接列表、步骤用途和删除能力保持一致，同时保留可审计的非秘密生成血缘，避免“界面已删但历史仍永久持有不可用密钥”的秘密生命周期。删除结果会报告解除凭据引用的历史阶段数量；真正失败时确认弹窗保持打开并就地显示原因。
- 风险：删除后旧文章不能沿用已删除连接普通重试，这是用户主动删除连接的预期后果；确认弹窗必须在执行前明确说明。历史非秘密 Provider 快照仍会展示原服务身份，但不再具备凭据或出站能力。
- 验证：core 覆盖仍分配步骤时拒绝和未分配时删除；Tauri 适配器覆盖同一绑定中目标 Provider 多修订凭据全部解除、其它 Provider 原样保留和清理队列登记；GUI 覆盖历史解绑成功反馈、严格 IPC 解码及删除失败在弹窗内可见。
- 恢复或调整标准：若未来需要恢复已删除连接的历史普通重试，必须另行设计用户可见的凭据恢复、同 ID 重新授权和审计流程；不得重新引入不可见的永久凭据引用。

## ADR-20260915-002：图片连接测试采用显式付费确认与一次性内存预览

- 日期：2026-09-15；状态：Accepted；确认人：`arden`。
- 关联需求：用户明确要求为图片 AI 服务增加测试功能。`change_id = FEATURE-IMAGE-AI-CONNECTION-TEST`；版本门禁返回 `required_version = 0.2.4`，同一未发布功能周期不重复提升 Minor。
- 背景：原规则为了避免意外费用，要求用户只能通过运行文章验证图片服务。该路径会同时创建文章包和运行历史，不适合在正式批量生成前单独定位图片端点、密钥、模型或下载协议问题。
- 取代关系：本决定仅取代 `ADR-20260914-001` 中“图片步骤不增加测试按钮”和 `ADR-20260914-002` 中“真实方舟调用只在明确运行文章时执行”的限制；两个 ADR 的步骤式配置、Provider 复用、方舟 wire 契约、临时 URL 安全与不可普通重试边界继续有效。
- 决定：图片步骤为当前已选择服务显示“生成测试图片”。打开或取消确认弹窗保持零出站；确认操作携带稳定 Provider ID、用户看到的修订号和本次付费确认，后端再次校验启用状态、图片能力、模型、参数、端点、凭据和无活动批次后，只发出一个真实图片生成请求。
- 请求与结果：测试复用正式图片阶段的服务修订、模型、尺寸、水印、超时与 wire 契约，只把固定且不含文章数据的极简 Prompt 发给服务商。原生层执行正式路径相同的方舟受限下载或 OpenAI Base64 解码，并完成 25 MiB 上限及 PNG/JPEG/WebP 魔数校验；结果只以受限 data URL 在当前确认弹窗内存预览，不返回远端 URL、本地路径、请求 ID、Prompt、原始响应或密钥。
- 留存与计费：测试不写 SQLite、文章、文章包、执行绑定、运行记录或素材目录；关闭弹窗即清除前端结果。每次确认最多一次请求，失败不自动重试，同一次确认不提供再次请求。超时、传输中断、无效图片或下载失败统一使用专门稳定错误，提示可能已经计费并要求先核对服务商控制台。
- 理由与影响：用户能在批量生成前独立验证真实图片链路并看到实际产物，同时把费用、修订竞争、秘密、临时 URL、孤儿文件和重复请求风险限制在可观察边界内。测试夹具不展示真实图片测试入口，避免把本地确定性结果误报为真实 AI。
- 验证：Rust 覆盖确认、修订、启用/模型/参数预检、请求构造、结果魔数和计费安全错误；现有 OpenAI/方舟 HTTP 契约继续覆盖请求与下载；严格 IPC 拒绝 URL、路径、错误 MIME、大小、修订或额外字段；GUI 覆盖打开/取消零调用、确认一次调用、临时预览、关闭清除和不确定失败不提供同次重试。
- 恢复或调整标准：若未来需要保留测试图或测试历史，必须另行定义存储生命周期、清理、容量和隐私边界；不得把当前一次性预览静默升级为持久素材。

## ADR-20260915-003：Grid 阶段状态格提供真正的单步生成

- 日期：2026-09-15；状态：Accepted；确认人：`arden`。
- 关联需求：用户明确要求在 Grid 的正文、简介、配图和格式状态位置直接单步生成。`change_id = FEATURE-GRID-STAGE-GENERATION`；版本门禁返回 `required_version = 0.2.4`，同一未发布功能周期不重复提升 Minor。
- 背景：原 Grid 的四个阶段格只有状态徽标，用户必须进入详情；详情中的“重新生成当前阶段”仍会由 worker 自动排队后续阶段，并要求三类 AI 全部配置，不能表达“只运行我点的这一步”。
- 决定：状态徽标继续只读，每个阶段格新增独立语义按钮。未开始阶段在当前包内首次生成；其它终态使用重新生成并按既有快照规则创建新包。单步完成只保存目标产物和尝试，绝不排队下一阶段；只有四个阶段及完整产物全部成功时才进入待审核。完整 SOP、普通失败重试和详情的既有继续运行语义保持独立。
- 依赖与配置：正文只校验标题；简介依赖成功正文；配图依赖成功正文和简介；格式依赖前三阶段全部成功。单步只冻结、读取和调用目标步骤的当前 Prompt/Provider/凭据，格式完全本地执行。一个文章包分步生成时只合并目标阶段的模板与 Provider，并沿用该包首次冻结的 Prompt renderer，不覆盖已经执行阶段的配置证据；正文重生成的新包使用当前 renderer，简介重生成只让已经执行过的配图过期。
- 竞争与计费：命令同时复核行版本、包版本和 worker 所有权，陈旧界面或快速双击在出站前失败关闭；单步、批量运行和失败重试共享同一同步动作锁。所有 Grid 配图调用先展示当前图片服务修订、模型、尺寸和水印并确认可能计费；取消零出站，一次确认最多一个请求，服务修订变化会拒绝，失败后必须关闭并重新确认。上次失败被稳定错误码标记为结果不确定时继续明确警告先核对服务商控制台，不能用“不可重试”代替结果不确定判断。
- 运行记录：运行记录以向后兼容的可空目标阶段区分完整 SOP 和单步运行；单步成功以目标阶段成功收口，即使整行仍是草稿也不得误报失败。重启恢复、失败、中断和取消同样按目标阶段判定。
- 验证：core 覆盖单步准备、依赖、版本和不自动推进；worker/仓储覆盖目标 Provider、格式零 AI、单步终态和重启恢复；Tauri 命令覆盖乐观锁、图片确认和修订竞争；GUI 覆盖语义按钮、依赖提示、同步防双击、图片取消零调用和确认一次调用。
- 恢复或调整标准：若未来要支持自由阶段图、并行阶段或批量单步，必须另行定义选择范围、依赖图、资源上限和计费确认；不得把当前单行单阶段入口静默扩展为隐式后续运行。

## ADR-20260915-004：Grid 直接预览产物并复用详情编辑入口

- 日期：2026-09-15；状态：Accepted；确认人：`arden`。
- 关联需求：用户要求正文、简介和配图产物像飞书多维表格一样直接在行内缩略显示，并可点击打开后手动编辑或查看。`change_id = BUG-GRID-CONTENT-PREVIEWS`；版本门禁返回 `required_version = 0.2.5`。
- 背景：原 Grid 的阶段格只显示状态与生成动作，用户不能在批量列表中辨认已有产物；查看正文、简介或配图还必须先点击通用详情再切换页签。直接把完整图片逐行送入 WebView 又会放大 2K 图片的 IPC、解码和内存成本。
- 决定：正文和简介单元格显示最多三行的纯文本缩略内容，点击后复用现有文章详情 Drawer，并直接落在对应的可编辑页签；配图单元格显示固定缩略图，点击后落在现有完整配图页签。缩略预览、状态徽标、单步生成、复选框和通用详情保持独立语义按钮，任何预览动作都不得触发 AI、创建尝试或改变文章状态。
- 过期语义：上游编辑后保留的旧正文、简介或配图允许继续预览，以帮助用户判断下一步；同一单元格必须继续显示真实的已过期或其它阶段状态，不能仅凭产物存在显示“已完成”。新尝试 ID 到达时重新读取对应配图缩略图。
- 图片边界：Grid 不复用完整图片 IPC。原生适配器按任务 ID 查询受管图片引用，规范化并限制在素材根目录内，只接受 PNG/JPEG/WebP 魔数；源长宽各不超过 `4096`、解码预算 `128 MiB`，缩放到 `192×128` 边界内并编码为最多 `256 KiB` 的 PNG data URL。路径、远端 URL、Prompt、密钥和原始响应均不返回 WebView。
- 资源治理：缩略图以 `IntersectionObserver` 在可视区域附近惰性加载，离开后从行组件释放；原生同时最多处理两个缩略请求。完整图片仍只在用户明确打开配图详情时沿用既有受限加载命令。
- 理由与影响：批量工作台可以直接扫视产物并一击进入编辑位置，同时不把“查看”混成“重新生成”，也不让几十张完整 2K 图片常驻 WebView。正文与简介不增加复制数据源，继续取自现有只读工作台视图。
- 验证：GUI 覆盖正文/简介缩略显示、点击目标页签回调、无图片零 IPC、可视区加载与离开释放、失败就地重试且不触发生成；严格 IPC 覆盖固定命令参数与 data URL 大小；Rust 覆盖大图按比例缩放和超限源尺寸失败关闭。
- 恢复或调整标准：若未来需要在 Grid 内直接编辑、显示多图或缓存缩略图，必须另行定义编辑冲突、素材数量、缓存容量和清理周期；不得把当前查看入口静默升级为自动保存或后台图片生成。
