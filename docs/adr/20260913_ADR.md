# 2026-09-13 ADR

## ADR-20260913-001：AI 服务生命周期与飞书真实初始数据

- 日期：2026-09-13；状态：Accepted；确认人：`arden`。
- 关联需求：补全 AI 服务的启停和删除，并把用户飞书表中的真实主题作为初始配置，随后使用用户本机 OpenAI 配置完成一次真实开发级 E2E。`change_id = FEATURE-PROVIDER-CONTROLS-FEISHU-INITIAL-DATA`；版本门禁返回 `required_version = 0.2.0`，同一未发布功能周期不重复提升 Minor。
- 背景：现有 AI 服务只能新增、编辑和测试连接；普通工作区没有业务初始行。用户已在正式本地库保存两个非秘密 Provider，但尚无文章、运行历史或执行绑定，因此重建数据库会丢失用户配置，仅在数据库文件不存在时播种又无法修复当前状态。
- 决定：Provider 增加持久 `enabled` 状态。停用会建立新修订、解除三个默认位并阻止新的测试和运行选择，已冻结并开始的批次继续按原绑定收口。删除要求服务已非默认且未被任何执行绑定引用；成功后保留历史修订，并从当前配置和凭据映射移除，未使用凭据进入现有可重试清理队列。
- 初始数据决定：内置飞书表 `QYSEO文章v1.3.0` 当前 14 条标题，精确保留共同标签 `跨境电商/营销策略` 与文章类型 `原创`。工作区 schema v5 保存一次性初始数据 revision；全新普通工作区直接写入，旧工作区仅在文章、运行历史和执行绑定均为空时加法写入，现有 Prompt、Provider 和凭据引用逐字段保留。无论注入或因已有内容跳过，revision 都标记已处理；用户后续删空不会复活种子。显式 E2E 夹具工作区不混入真实业务种子。
- Prompt 决定：正文和配图默认模板纳入飞书当前真实约束，并继续使用本产品的关键词、内容要求和简介变量。飞书没有暴露独立简介公式，简介沿用当前 80–120 字直接输出契约；Markdown→HTML 仍为确定性本地步骤，不为追求“全部 AI”增加不必要调用。
- OpenAI 边界：应用保持可配置的 OpenAI-compatible 契约。用户只在本机系统凭据库录入 API Key；正文/简介可使用 Chat Completions 兼容文本模型，配图使用 Image API Base64 响应模型。真实 E2E 只运行一条种子以限制费用，不记录密钥或原始认证数据，也不等同发布候选验收。
- 理由与影响：启停让服务能够暂时退出调度而不破坏冻结批次；受引用删除失败关闭避免“界面已删但历史仍暗中持有密钥”的假象；revision 账本同时覆盖全新库和当前已有 Provider 的空内容库，且不会覆盖用户数据。
- 风险：不同 OpenAI 账号可访问的模型和额度不同，真实 E2E 可能因账号权限、配额、账单或内容策略失败；这类外部结果必须如实展示，不可降级到夹具冒充成功。严格删除语义意味着已进入文章血缘的服务需先删除相关任务/绑定后才能清理。
- 验证：core 覆盖启停、默认位、引用删除和迁移；存储覆盖 fresh/v4 空白/已有内容/重开/删除后不复活；GUI 覆盖 Switch 与父容器不串扰、确认删除、禁用测试和中英文反馈；最后在新构建的普通应用中使用用户本机 OpenAI 配置跑一条真实种子到待审核，并复核现有 Provider 未丢失、种子不重复。
- 恢复或调整标准：如用户后续需要删除仍被历史引用的 Provider，应先单独设计“删除配置但保留/轮换历史凭据”的迁移和审计语义；如需要飞书持续同步，应另行确认字段映射、冲突、增量标识和回写权限，不把一次性 revision 改成隐式网络同步。
