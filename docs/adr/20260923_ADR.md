# 2026-09-23 ADR

## ADR-20260923-002：完整纠正产品身份并启用全新本地命名空间

- 日期：2026-09-23；状态：Accepted；确认人：`arden`。
- 关联需求：用户明确要求把项目目录和命名全部改为“毕方内容生产助手”，英文名按该中文名确定，并且当前维护树不保留此前错误的项目身份与相关错误记录。`change_id = BUGFIX-FULL-PRODUCT-IDENTITY-CORRECTION`；版本门禁返回 `required_version = 0.2.13`。
- 决定：中文名固定为“毕方内容生产助手”，英文名固定为 `Bifang Content Production Assistant`，项目 ID 固定为 `bifang_content_production_assistant`，kebab 前缀固定为 `bifang-content-production-assistant`。仓库根目录、CLI/core/GUI 目录、Rust crate 与二进制、前端 package、Tauri identifier、深链接协议、系统凭据服务、设备偏好键、E2E 环境变量、测试临时路径、当前文档和两份许可证全部使用该身份派生值。
- 历史边界：当前维护树移除被撤销的错误身份决定与对应 Changelog 条目，并归一化旧规格中的身份字段；功能范围、日期、验证结论和版本门禁审计状态不伪造。Git 对象和提交历史不做破坏性改写，远端不执行 force-push。
- 数据边界：不保留旧身份兼容别名，也不自动读取或复制旧应用命名空间中的工作区、窗口状态、设备偏好与系统凭据。改名过程不删除这些宿主数据；如需迁移或清理，必须重新确认精确位置、凭据边界与可恢复方案。
- 理由与影响：代码仓库、可执行接口和桌面宿主使用同一产品身份，GitLab 默认树不再暴露错误目录和包名。完整更换应用标识避免继续积累隐藏旧前缀，但已有安装会被操作系统视为不同应用，外部脚本也必须改用新 CLI 名称。
- 风险：旧命名空间中的用户数据和凭据不会自动出现在新应用中；旧深链接与旧 CLI 名称失效。仓库根目录移动还会改变 Git common-dir 绝对路径，必须修复并验证所有登记 worktree 的回链。
- 验证：先运行身份脚本 preview，再应用无覆盖改名；精确扫描当前维护树的旧身份文本和路径；使用 Cargo 重新生成锁文件并执行 metadata、格式、core/CLI 测试和 GUI 定向测试；解析 Tauri/前端配置并逐个验证登记 worktree。普通开发不宣称发布候选、签名、公证、Windows 宿主或真实用户数据迁移已验收。
- 恢复或调整标准：若需要兼容旧工作区、凭据、深链接或 CLI 名称，必须新增受限迁移决定，禁止静默恢复旧标识。回退身份时使用同一改名脚本反向预览并同步 Product Spec、ADR、Changelog、许可证和宿主标识。

## ADR-20260923-001：产品 CLI 增加显式工作区的文章只读查询

- 日期：2026-09-23；状态：Accepted；确认人：`arden`。
- 关联需求：用户在 Task 8 完成后明确要求为程序“增加 cli 部分”，并确认实施只读文章列表与详情边界。`change_id = FEATURE-ARTICLE-READ-CLI`；版本门禁返回 `required_version = 0.2.12`。
- 背景：产品元数据已经声明 CLI 与 GUI 两种接口，但现有产品 CLI 只提供 `sop describe`，无法查看 GUI 本地工作区中的文章。GUI 的现有工作区仓储会创建数据库、迁移 schema、注入初始数据、恢复中断状态并保存，不能作为只读 CLI 复用。
- 决定：增加 `article list --app-data-dir <DIR>` 与 `article get --app-data-dir <DIR> --id <ID>`，保留人类输出和统一 `--json` 信封。调用者必须传入现有绝对非符号链接应用数据目录；CLI 只以 SQLite read-only、禁止创建模式读取其中现有 `content-workbench.sqlite3` 的 schema v11 单行快照。列表顺序固定为创建时间倒序、相同时间按 ID 倒序；详情按大小写敏感 ID 精确查找。
- Core-first 与数据边界：core 新增窄只读仓储端口、排序/查找用例、稳定错误与安全 DTO；SQLite 路径和协议只留在 CLI 适配器。列表只提供身份、输入、版本、状态和时间；详情增加当前文本产物、图片存在性、编辑修订和历史数量。当前及历史本地图片引用、历史正文、工作区其它配置均不离开持久层。
- 零写入与副作用：CLI 不复用 GUI 仓储，不执行迁移、规范化、初始数据注入、中断恢复或保存；不创建缺失目录/数据库，不扫描用户目录，不读取图片文件、Provider、系统凭据、网络、stdin 或外部进程，也不触发 AI 与飞书调用。旧或未来 schema 必须失败关闭并提示先启动当前桌面应用。
- 协议与错误：成功机器命令名为 `article.list`、`article.get`。路径或 ID 参数无效退出 `2`，数据库/快照/文章不存在退出 `3`，安全打开或读取不可用退出 `6`，无效快照或 schema 不匹配退出 `10`；稳定错误消息不得包含绝对宿主路径、数据库正文或底层驱动错误。
- 理由与影响：该边界补齐已声明 CLI 接口的最低可用文章查询能力，同时让排序、精确查找、投影和错误事实由 shared core 统一维护。显式目录避免平台路径推断与身份漂移；严格只读连接避免命令行查询静默改变用户工作区。
- 风险：调用者必须自行找到桌面应用数据目录；尚未由当前桌面版迁移到 schema v11 的工作区不能直接查询。日常实现只验证当前 macOS 开发宿主和隔离 SQLite 夹具，不宣称 Windows 宿主、发布候选或真实用户数据库已验收。
- 验证：运行 core 定向测试与 CLI 黑盒测试，覆盖默认排序、精确查找、图片引用脱敏、特殊字符路径、查询前后数据库字节和目录文件集合不变、缺失数据库不创建、非当前 schema、稳定退出码、JSON 单文档及 stdin 持续打开仍退出；同时执行既有 CLI 回归、格式和 diff 检查。不执行发布构建、GUI E2E 或渠道验收。
- 恢复或调整标准：若后续需要自动发现工作区、兼容旧 schema、分页/筛选、完整历史、写入或运行能力，必须重新确认产品边界、数据泄露面和迁移/并发语义；不得从本只读查询自动扩展。回退时删除两个文章命令和只读端口，不改变现有 GUI 数据与 `sop describe`。
