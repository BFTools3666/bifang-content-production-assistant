# 2026-09-29 ADR

## ADR-20260929-005：独立小红书发行版不复用 SEO 公共服务身份

- 状态：Accepted；关联需求：用户要求独立小红书工具并合并到公司最新源码。`change_id = FEAT-BENCHMARK-STYLE-DUAL-EDITION-20260928`；整合时 `required_version = 0.2.18`。
- 背景：公司公共服务已登记 SEO 应用，新的小红书发行版没有相应登记证据。复用 SEO release code 会混合产品统计，并可能展示错误产品的更新。
- 决定：SEO 保持公司公共服务协议；小红书以独立 APP_ID 运行，在未登记独立端点之前，生产公共服务 transport 为未配置，不发统计或版本请求。用户自己的 AI Provider、采集、风格库和写作功能保持独立工作。
- 影响与理由：保留已登记产品能力，避免向另一产品的服务提交请求或打开其更新下载。
- 风险：小红书的服务端版本发现与统计暂不可用；没有提供或猜测未登记的生产路由。
- 验证：配置测试分别覆盖 SEO 注册路由和小红书未配置 transport；运行结果以本次 PR 记录为准。
- 恢复标准：取得公司小红书 APP_ID、统计路由、release code 的真实登记证据后，通过独立改动接入并验证。


## ADR-20260929-004：两个创作者发行版首次启动固定简体中文

- 状态：Accepted；关联需求：用户指出界面全部英文，要求中文工具。`change_id = FEAT-BENCHMARK-STYLE-DUAL-EDITION-20260928`；`required_version = 0.2.18`。
- 背景：原有宿主在没有语言偏好时跟随系统语言；本机被识别为英文，首次启动显示英文。SEO 与小红书两个发行版服务中文平台和中文创作者。
- 决定：没有保存语言偏好时，Rust 宿主、React 初始化和异常回退统一为 `zh-CN`；Windows NSIS 安装向导仅使用 `SimpChinese`。已保存的中文或英文选择优先。保留官方 OS 插件注册，不增加 WebView 权限。
- 例外：按用户的明确要求，覆盖 `desktop-add-gui-system-locale` 的首次启动跟随系统与未知语言回退英文规则。语言仍仅由原有 Rust 窄命令读写。
- 影响与风险：英文系统中的新用户也首先看到中文；原有明确保存的英文偏好不会被强制覆盖。修改语言会同步 React 和原生托盘，并持久化到当前发行版的设备配置目录。
- 验证：回归首次启动中文、未知语言中文、保存偏好优先及偏好写入复读；真实窗口确认导航和页面中文；最终 Windows 安装包须确认安装向导、首次启动和重启后的中文显示，尚未执行的宿主测试不能声明通过。
- 调整标准：只有用户明确要求按系统自动选择语言时才恢复该行为；不得在前端单独增加语言探测。

## ADR-20260929-001：接入隐私最小化 CloudBase 统计与共享版本发现服务

- 日期：2026-09-29；状态：Accepted；确认人：`arden`。
- 关联需求：用户要求检查当前统计模块是否接入环境 `bftoos-sh-d3ga7hahz59229f0a` 与版本更新服务；云端登记和统计资源已部署，但当前客户端没有接线，因此继续使用 `D:\workspace\bifang-operations-assistant` 的冻结协议完成客户端接入。`change_id = FEATURE-CLOUDBASE-PUBLIC-SERVICES`；版本门禁返回 `required_version = 0.2.17`，本发布周期功能位已存在，不额外提升版本。
- 决定：shared core 持有十字段 `daily_active`、严格七字段 application-version 响应、状态真值表和安全公网 HTTPS 规则；Tauri 适配器持有固定 CloudBase 路由、状态文件、日期认领、HTTP transport、低权限凭据、下载地址与退出生命周期；React 只展示 Rust 判定结果。
- 隐私边界：统计默认关闭并由设置页显式开启/撤回，只生成本应用随机 UUID v4，按北京时间每日最多尝试一次且请求失败不重试；不收集账号、硬件标识、AI 配置、凭据或创作内容。隐私说明固定为 `docs/privacy.md`。
- 版本边界：版本发现固定使用 `/tools/version-control/v1/versions/{code}/{currentVersion}`，构建宿主必须同时注入应用专属 Key/Secret，任一缺失即零 GET。服务提示按纯文本展示，下载 URL 只在 Rust 中保存和打开；强更由根级门阻断，`stopUpdate` 仅表示暂停分发。
- updater 边界：官方 Tauri updater 插件仍保持 `NotConfigured`、空 endpoint 与零出站，不承担本次版本发现，也不自动下载或安装候选。
- 云端事实：运营助手提交 `fad8cc79217bd3bbead6063721ba646a4b12faa2` 已登记本应用，部署独享 telemetry 函数、路由和集合，并通过合成 `daily_active` 在线验证；共享版本函数保持既有部署。本次不重复部署、不生成凭据、不购买资源、不写版本记录。
- 风险：当前构建没有运行时版本凭据，因此只能验证缺失凭据的零请求路径和注入 transport 的离线协议；真实客户端版本 E2E 仍未执行。系统浏览器能否成功处理下载链接仍依赖宿主默认 HTTPS handler。
- 验证：执行 core 与 GUI Rust 定向测试、前端公共服务定向测试、TypeScript 类型检查、Profile v2 校验/派生和遗留扫描；记录 CloudBase 已有收据。普通开发不声明发布候选、签名、公证、安装包或跨平台最终产物已经验收。
- 恢复或调整标准：如需默认启用统计、增加字段、跨应用关联、自动下载安装、广告、生成生产凭据或改变 CloudBase 环境，必须新增产品决定并重新评估隐私、凭据、付费与发布门禁。回退时删除客户端调用与设置入口，不删除云端历史数据或共享服务。

## ADR-20260929-002：版本发现使用独立 Kaiwhale 网关

- 日期：2026-09-29；状态：Accepted；确认人：`arden`。
- 关联需求：用户确认 application-version 的 App Key 为 `versionControl`、App Secret 由其提供、入口为 `https://gateway.kaiwhale.com`，并明确 HTTP 400 是本次网关连通性检查的正确结果。该决定延续 `change_id = FEATURE-CLOUDBASE-PUBLIC-SERVICES`，版本门禁幂等返回 `required_version = 0.2.17`。
- 决定：匿名统计继续固定使用 CloudBase 环境 `bftoos-sh-d3ga7hahz59229f0a`；版本发现改用单层基址 `https://gateway.kaiwhale.com/tools/version-control/v1`。非敏感 App Key 固定在 Rust 可信层，App Secret 仅通过 `BIFANG_CONTENT_PRODUCTION_ASSISTANT_VERSION_APP_SECRET` 在构建时注入，不写入 Git、Profile、日志或文档。
- 响应边界：无凭据连通性探针对基址和完整版本 URL 均返回预期 HTTP 400，证明网关地址可达；运行时只有 HTTP 200、JSON Content-Type 且通过严格七字段校验的响应才可形成更新状态，400 继续安全降级为检查失败。
- 验收边界：本次不执行带明文 Secret 的持久化或日志化命令，也不把 400 声明为版本业务 E2E。真实发布构建仍须安全注入 Secret，并对 200/七字段响应、下载 URL 和平台发布流完成客户端验证。

## ADR-20260929-003：修正 Windows 发布流并固定版本凭据

- 日期：2026-09-29；状态：Accepted；确认人：`arden`。
- 关联需求：负责人明确要求把 Windows 版本路径从 `bifang-content-production-assistant-windows-x64` 改为 `bifang-content-production-assistant-windows`，并将已提供的 App Secret 直接写入代码。`change_id = BUG-VERSION-WINDOWS-CODE-EMBEDDED-SECRET`；版本门禁返回 `required_version = 0.2.18`。
- 决定：Windows x64 构建固定使用不带架构后缀的发布流 code；App Key 与 App Secret 均固定在 Rust 可信层，不再依赖构建环境变量。该决定取代 ADR-20260929-001 与 ADR-20260929-002 中关于凭据构建注入、缺失凭据零请求及 Secret 不入库的约束。
- 风险接受：固定 Secret 会进入 Git 历史和编译产物，不能视为保密材料；后续若需要轮换，必须同时更新服务端和客户端并以新的版本变化交付。
- 验收：使用代码中的固定凭据对修正后的 Windows 路径发起无 body GET，以负责人指定的 HTTP 400 作为网关连通性结果；运行时仍只把严格 HTTP 200 七字段 JSON 解释为版本业务结果。


## ADR-20260929-006：原框架中的四步写作与业务导航

- 状态：Accepted；用户先批准预览，随后明确修正 AI/飞书入口与 Windows 优先验收顺序。
- `change_id = FEAT-ARTICLE-WRITING-SOP-20260929`；`required_version = 0.2.20`。
- 决定：主工具名称恢复“毕方内容生产助手”，不改变 application identifier、工作区、凭据或公司统计协议。原 sidebar 模板切换为 detailed，使用原 248/76px 两态与原偏好机制；一级业务为写文章、找对标、风格库、我的文章。
- 写作首页四步呈现，平台位于业务内；原批量工作台通过 `/batch` 保留。AI、飞书、提示词和运行记录保留原实现与路由，在设置和对应动作中进入。
- 方案选择：独立新建 GUI 会重复成熟的系统能力、数据规则和连接器边界；在原框架内组合既有用例可以保留这些规则，新增正文转入批量流程的用例放入 core，宿主仅负责原子写入与导航。
- 兼容与限制：不会迁移或清空已有资产。新的正文转入动作幂等；批量正文已被修改时拒绝覆盖。HTML 导出是安全转义的文本，不宣称原有带配图 HTML 排版已完成。
- 验收：先完成功能分支代码与 Windows 安装验收，之后才合并主分支；新版本的真实宿主证据单独记录，不沿用旧 macOS Fixture 结论。

## ADR-20260929-007：首次写作接入 AI 及输入保护

- 状态：Accepted；`change_id = BUG-AI-KEY-ONBOARDING-DISCOVERY-20260929`；`required_version = 0.2.21`。
- 决定：未接入可用文本服务时禁止开始生成并给出接入向导；读取失败单独提供重试，不展示空配置成功态。DeepSeek 默认模型由 core 统一提供，首次向导只收用户 Key，并复用原保存命令与系统凭据库。
- 不自动运行连接测试或生成；保存本身零出站，不改已有图片默认服务。实际生成或用户明确测试仍可能计费。
- 写作材料、步骤与尚未提交的编辑表单只在当前进程的 UI 会话保存；原始业务对象由 Query/core 拥有，保存成功后删除表单输入。跨路由回来不会被后台旧正文覆盖；关闭软件前需要保存。
- 验证范围：自动化覆盖无 Key 禁用、配置读取失败、保存无自动调用、失败不重试、输入跨页面保留与未保存禁止导出；真实 Windows Key/联网/持久化仍需安装包验收。
