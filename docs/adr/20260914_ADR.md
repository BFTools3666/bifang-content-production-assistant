# 2026-09-14 ADR

## ADR-20260914-001：AI 配置采用步骤优先、连接复用的信息架构

- 日期：2026-09-14；状态：Accepted；确认人：`arden`。
- 关联需求：用户明确要求正文、简介、图片所用 AI 分开配置，解决现有单张服务表单同时堆叠三阶段字段、难以理解的问题。`change_id = FEATURE-STAGE-CENTRIC-AI-CONFIGURATION`；版本门禁返回 `required_version = 0.2.0`，同一未发布功能周期不重复提升 Minor。
- 背景：当前 Provider 数据模型已经允许正文、简介、图片分别使用模型、参数和默认服务，但 GUI 以底层服务为中心，把三组字段连续放在同一表单内。该布局把“工作流步骤”和“网络连接”混在一起，用户难以确认正在配置哪个生成步骤，也容易误以为三个步骤必须共用一套 AI。
- 决定：AI 服务页以固定 SOP 的正文 AI、简介 AI、图片 AI 为三个一级步骤入口。当前步骤只展示并编辑本步骤的模型、参数、默认服务和适用连接测试；服务名称、API 根地址、密钥状态、启停和删除进入独立的服务连接管理区域。
- 复用与兼容：同一 Provider 仍可同时服务三个步骤，底层配置、修订和系统凭据均不拆分、不复制、不迁移。步骤编辑必须从完整已保存 Provider 建立草稿，只修改当前步骤字段，再把完整对象交给 core 保存；未显示步骤的模型、参数和默认位保持逐字段不变。编辑服务连接也必须保留所有步骤字段。
- 新增语义：从当前步骤添加新服务时，只激活和校验当前步骤的模型及默认位，另外两个未显示步骤的默认位固定为 false，避免后端草稿的旧默认值造成隐式跨步骤绑定。后续可分别进入其它步骤补充同一服务。
- 页面状态：当前 AI 步骤使用应用根 Jotai store 在进程内跨路由保留，不写入数据库或浏览器存储；全新 store 默认正文 AI。
- 连接测试：正文和简介保留最小文本连接测试。图片步骤明确提示需通过用户主动运行文章验证，不增加会意外产生图片费用的测试按钮。
- 理由与影响：用户操作对象与真实 SOP 一致，默认服务归属和参数影响范围可直接理解；连接和凭据仍集中管理，避免同一密钥出现三份生命周期与安全状态。该变化属于 GUI 信息架构，现有 core 模型与数据库 schema 无需改变。
- 风险：同一 Provider 在三个步骤中都可见时，分阶段保存若错误地从空草稿组装会清空隐藏字段；必须通过提交参数断言覆盖三个方向。停用或删除属于底层服务动作，会同时影响它承载的全部步骤，因此只在服务连接管理区提供并明确说明范围。
- 验证：GUI 测试覆盖三个步骤入口、当前步骤字段隔离、跨路由状态、已有三阶段 Provider 复用、新服务默认位隔离，以及编辑任一步骤/连接时其它步骤配置不变；既有 core Provider 生命周期测试继续作为底层规则证据。
- 恢复或调整标准：若未来不同步骤必须使用完全不同的认证方式或网络协议，再单独设计多种连接类型和凭据引用；在此之前不得通过复制 Provider 或密钥来模拟分阶段配置。

## ADR-20260914-002：火山方舟图片采用独立 Provider 类型与 URL 即时落盘

- 日期：2026-09-14；状态：Accepted；确认人：`arden`。
- 关联需求：用户明确给出火山方舟 Ark v3 图片生成契约，指出现有 OpenAI Base64 图片路径无法连接。`change_id = FEATURE-VOLCENGINE-ARK-IMAGE-PROVIDER`；版本门禁返回 `required_version = 0.2.0`，同一未发布功能周期不重复提升 Minor。
- 背景：现实现只允许 OpenAI 标准像素尺寸，仅发送 `model/prompt/size`，并只接受 Base64；用户所用方舟接口要求 `2K`、单图、URL 返回、非流式和水印字段，返回值是有时效的下载 URL。根据 host 或 URL 猜测协议会让历史重试产生不稳定请求，也可能把图片专用连接误用于文本。
- 决定：新增仅支持图片能力的 `VolcengineArkImage` Provider 类型，并新增冻结的 `VolcengineArkUrlV1` wire 契约。方舟首版固定发送 `sequential_image_generation=disabled`、`response_format=url`、`stream=false`，公开配置只包含推理接入点 ID、`2K`、水印和超时；这些参数和契约版本共同进入幂等身份。
- 地址与凭据：持久配置保存方舟 API 根地址 `https://ark.cn-beijing.volces.com/api/v3`，适配器统一追加 `images/generations`。方舟服务只参与图片阶段的默认位与执行绑定；它使用自己的系统凭据引用，界面不回填密钥。服务类型或实际请求端点变化时，已有密钥必须同步轮换。
- URL 安全与计费边界：POST 的 Bearer 只发送给用户保存的方舟端点。响应 URL 由独立、禁止重定向的请求立即下载，不转发 Bearer 或幂等头；生产只接受受限的 HTTPS 火山对象存储来源，并执行响应体积和 PNG/JPEG/WebP 格式检查。临时 URL 和查询签名不写入持久化、WebView、日志或错误。Ark POST 发出后结果未知、成功后的下载失败，以及应用退出时仍在运行的 Ark 配图，统一成为不可普通重试的安全错误，明确提示用户核对方舟记录并手动重新生成，避免“仅重试失败”再次调用付费生成；下载端 403/404 不复用生成 API 的鉴权或模型错误文案。Core 和 GUI 的普通重试入口都必须检查失败对象的 `retryable` 标志。
- 兼容与迁移：Provider 配置 schema 提升至 v5、工作区 schema 提升至 v6。旧配置缺失水印时迁移为 `false`，旧 OpenAI Provider 及其三种 Base64 冻结契约保持不变；新方舟绑定明确冻结 `VolcengineArkUrlV1`，当前 schema 缺失契约继续失败关闭。
- 兼容修订：`BUGFIX-LEGACY-ARK-PROVIDER-UPGRADE` 的版本门禁返回 `required_version = 0.2.2`，工作区 schema 提升至 v7。只有 v6 当前集合中地址精确为 `https://ark.cn-beijing.volces.com/api/v3/images/generations`、不承担正文或简介且图片模型非空的旧 OpenAI-compatible 配置会原地切换为方舟类型，并规范化为 `/api/v3` 根地址、`2K` 和水印；原服务 ID、修订、超时、默认位及系统凭据引用不变，迁移不解密、不复制凭据，也不改写 Provider 历史或冻结执行绑定。该完整旧地址与新根地址追加路径后的实际认证目标相同，因此不构成把密钥发送到新端点；任何非精确匹配继续保持原配置并要求用户显式新建或轮换密钥。
- 验证：core 覆盖能力、草稿、参数与迁移；Mock HTTP 覆盖精确方舟请求体、URL 下载不带秘密、来源/重定向/大小/格式拒绝与 OpenAI 回归；GUI 覆盖图片页方舟预设、文本页隔离、严格 IPC 解码和阶段保存不串改。真实方舟调用只在用户录入有效 ARK API Key 并明确运行文章时执行，避免测试按钮产生费用。
- 恢复或调整标准：若方舟后续需要多图、流式或更多尺寸，必须以新的公开参数边界和 wire 契约版本扩展；不得静默改变既有执行绑定的请求体。
