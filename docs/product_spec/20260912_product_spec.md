## 产品目标

本产品是一款面向批量内容运营的本地桌面工作台。用户在类似飞书多维表格的
Grid 中一次录入或粘贴多个文章标题，选择需要处理的行并启动固定 SOP，随后在
同一行观察正文、简介、配图和格式产物的生成状态，精确重试失败阶段，并在详情
界面审核、编辑和批准最终文章包。

首要消费者是需要一次生产几十篇文章的内容运营人员。GUI Grid 是主要工作界面；
共享 Rust core 是任务规则与状态的唯一事实源，CLI 仅保持薄适配器边界。

## 核心输入与输出

每一行至少包含文章标题，可选包含关键词和内容要求。运行时冻结该行输入、各步骤
Prompt 模板版本以及所选 AI Provider/模型配置。

每一行最终形成一个可追溯的文章包：

- 标题和输入约束；
- Markdown 规范正文；
- 文章简介；
- 一张配图及生成元数据；
- 从规范正文派生的可复制 HTML；
- 阶段状态、错误、尝试记录与审核结论。

## MVP 包含范围

### Grid 批量工作台

- 批量粘贴多行标题，空行不创建记录；重复标题保留为独立记录并明确提示。
- 支持单选、全选当前结果、取消选择、搜索、状态筛选和基础排序。
- “运行所选”只处理明确选中且校验通过的行，并在运行前显示可运行和跳过数量。
- 主表显示标题、总体状态、正文/简介/配图/格式阶段、更新时间和错误摘要。
- 单行失败不得中断同批其他行；支持仅重试失败阶段与显式重新生成。

### 固定内容 SOP

1. 校验标题和行级输入。
2. 通过文本 Provider 生成 Markdown 正文。
3. 基于指定正文版本生成文章简介。
4. 基于标题、正文摘要和图片 Prompt 生成配图。
5. 从规范正文生成 Markdown/HTML 格式产物。
6. 校验必需产物并进入待审核。

正文、简介、配图和格式分别具有独立状态。普通重试沿用当前文章包版本，只执行失败
或中断阶段；“重新生成”创建新版本，不能覆盖旧成功产物或已批准版本。

### 详情与审核

- 通过明确的“查看详情”按钮打开详情 Drawer。
- 展示正文、简介、配图、Markdown、HTML、Prompt/Provider 版本和运行记录。
- 支持编辑正文与简介、单阶段重新生成、批准当前完整文章包或退回修改。
- 正文修改后，所有依赖它的产物标记为已过期；首版不允许确认沿用旧产物，完成重新生成前禁止批准。
- 批准绑定不可变的文章包版本，后续重新生成回到待审核而不改变历史批准版本。

### Prompt 模板与 AI 服务

- 正文、简介、配图分别管理具备稳定 ID、版本、变量声明和内容的 Prompt 模板。
- 保存前拒绝未知变量、缺失必需变量和空模板；渲染预览不调用外部 AI。
- core 定义厂商无关的文本和图片生成端口；Provider 专属网络与鉴权只存在于适配器。
- MVP 提供可配置的 OpenAI-compatible 文本与图片真实调用路径；不同步骤可选不同配置。
- 自定义服务地址是用户明确录入的受信任配置，可指向其自托管 HTTPS 服务；地址不得来自文章、AI 响应或深链接，界面必须提示测试/运行会向该地址发送密钥和内容。
- 非秘密配置本地持久化；API 密钥只写入系统凭据库，不写入数据库、日志、截图或错误文本。
- Provider 未配置时保持零出站并返回稳定错误；正式界面不得用测试替身冒充真实 AI。

### 本地持久化与恢复

- 文章、文章包版本、阶段状态、尝试、模板和非秘密 Provider 配置在重启后保留。
- 产物与成功状态必须原子保存，不能出现“状态成功但产物缺失”。
- 异常退出后原运行中阶段恢复为“已中断/可重试”，不得永久卡住。
- 批次具有有界并发、超时、取消归属和按 Provider 的限流；未配置时不发出网络请求。

## 状态与业务不变量

总体状态至少包括：草稿、已排队、运行中、待审核、已批准、部分失败、已取消、
已中断。阶段状态至少包括：未开始、已排队、运行中、成功、失败、已过期、已取消。

- 总体状态由阶段状态和审核状态推导，GUI 不得直接写入。
- 待审核要求全部必需阶段成功且无过期产物。
- 每个派生产物记录输入版本、模板版本、Provider、模型和尝试 ID。
- 同一任务版本与阶段的普通重复执行具备幂等语义。
- 人工编辑、审核结论和已批准版本不得被批量操作静默覆盖。
- 外部 AI 调用只能由用户明确运行或重新生成触发。

## 可靠性与体验约束

- 一行或一阶段失败不得终止整批；错误需给出稳定分类与恢复动作。
- 测试默认不调用真实付费服务，真实 Provider 冒烟必须显式启用并提供凭据。
- 中英文文案完整；状态不能只靠颜色表达；批量操作与审核可通过键盘完成。
- 保留现有 compact 80px 侧栏以及设置、关于、赞助等已确认宿主页面契约。
- 960×640 下核心流程可完成；Grid 允许自身横向滚动，页面整体不得横向溢出。

## 可观察成功标准

- 批量粘贴 20 个有效标题会创建 20 个独立任务；空行不创建，重复项不被静默合并。
- 选择任意子集运行时，未选行绝不入队；一行图片失败时其他行继续完成。
- “仅重试失败”不重复调用成功阶段；“重新生成”产生可追踪的新版本。
- 编辑正文会让依赖产物过期并阻止批准；已批准版本在重启和后续批次后保持不变。
- 应用重启会把遗留运行中阶段恢复为可重试的中断状态。
- Provider 的鉴权、限流、超时、网络和无效响应映射为稳定错误，且 UI/日志不泄露密钥。
- 用户可完整完成：批量添加 → 选择部分行 → 运行 → 查看局部失败 → 精确重试 →
  打开详情 → 审核批准。
- 自动化回归覆盖 core 状态/幂等/失败隔离、持久化恢复、Provider 映射以及 GUI 的批量
  添加、选择、运行、重试、详情和批准路径。
- 真实运行应用至少形成 Grid、局部失败、重试后、详情审核、Prompt/Provider 配置和最终
  批准状态的截图证据；证据必须标明真实 Provider 或测试夹具，且不出现密钥。

## 明确非目标

- 不复制飞书的通用数据库、公式、自动化、视图设计器、评论或实时协作。
- 首版不接飞书 OpenAPI，不回写原多维表格；飞书只作为 Grid 交互参考。
- 不自动登录或发布到 CSDN、百家号等内容平台，不规避验证码或平台风控。
- 不包含关键词研究、排名监控、自动事实核验、抄袭判定或 SEO 效果承诺。
- 不提供自由工作流、任意脚本、动态第三方插件或 AI Provider 市场。
- 首版固定输出 Markdown 与 HTML，不建设开放式格式设计器。
- 不建设云端团队后台、多租户、计费、跨设备同步或完整 CLI 交互产品。
- 构建发布候选、签名、上传和渠道发布不属于本次 MVP。
